# TRANCOM · Telegram-бот оперативних чек-листів водія

Рабочий прототип. Водитель проходит рейс по кнопкам (7 этапов + правила),
всё пишется в базу, по завершении рейса автоматически формируется
красивый .docx отчёт, копируется в OneDrive и добавляется строкой в
общую таблицу-дашборд по всем рейсам. Менеджер получает уведомления
и отчёт прямо в Telegram.

## Что уже готово

- **Структура рейса ровно как вы описали**: обязательные этапы по порядку
  — Завантаження → Старт → Стоп → Вивантаження (внутри каждого — исходный
  текст чек-листов из вашего документа). В любой момент рейса доступны
  необязательные, повторяемые сколько угодно раз действия: ☕ Пауза,
  🚨 ЧП, ➕ Додаткова зупинка — они не блокируют движение по этапам.
- **Машина и груз запоминаются за водителем.** Первый раз — вводит вручную
  (тягач, прицеп, груз, маршрут). Со второго рейса бот сам спрашивает
  "Той самий автомобіль?" / "Вантаж такий самий?" с кнопками Так/Ні —
  печатать заново не нужно, если ничего не изменилось.
- Связка водитель + машина + груз хранится в самом рейсе (это и есть
  единица учёта в отчётах и дашборде).
- Фото прикрепляются к нужным пунктам (где в чек-листе написано "зробив фото")
- Итоговый Word-отчёт по рейсу: кто, на чём, что вёз, хронология по всем
  4 обязательным этапам, список пауз/доп.остановок/ЧП с фото
- Общая таблица `dashboard.xlsx` со строкой на каждый рейс (для менеджера),
  включая счётчики пауз, доп.остановок и ЧП
- Загрузка отчёта, фото и таблицы в OneDrive — уже настроено и готово к работе
  (см. ниже, credentials уже прописаны)

## Установка (5 минут)

```bash
cd trancom_bot
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` — **BOT_TOKEN** и OneDrive уже заполнены, осталось только:

1. **MANAGER_CHAT_IDS** — chat_id менеджеров (кому слать отчёты).
   Проще всего: менеджер пишет боту [@userinfobot](https://t.me/userinfobot),
   тот присылает его Id. Несколько ID — через запятую.

(Если понадобится создать другого бота — токен берётся у
[@BotFather](https://t.me/BotFather), команда `/newbot`.)

Запуск:

```bash
python bot.py
```

Всё, бот работает — включая OneDrive: он уже настроен через `.env.example`
(см. раздел ниже), отчёты и фото сразу начнут появляться в вашей папке.

## Как это выглядит для водителя

1. `/start` → один раз вводит имя и телефон
2. "🚀 Почати новий рейс" → выбирает машину (или добавляет новую) →
   пишет груз и маршрут
3. Один экран с правилами компании → "✅ Ознайомлений(а)"
4. Дальше — 7 экранов чек-листов. На каждом пункте просто нажимает
   кнопку: ⬜→✅. Пункты с 📷 требуют реального фото — бот попросит
   его прислать и сам отметит пункт
5. Когда все пункты этапа отмечены — появляется кнопка "➡️ Далі"
6. После последнего этапа бот сам собирает отчёт и отправляет менеджеру

Если водитель закрыл бота на середине рейса — `/start` → "▶️ Продовжити
поточний рейс" вернёт его туда же, где остановился.

## OneDrive — уже настроено, ничего делать не нужно

Использую то же Azure-приложение, что и в вашем существующем invoice-боте
(тот же tenant, тот же клиент, права `Files.ReadWrite.All` уже выданы и
подтверждены админом). Credentials уже прописаны в `.env.example` —
просто скопируйте его в `.env`, ничего в Azure регистрировать не нужно.

Каждый день бот сам создаёт в вашей папке подпапку с датой (`2026-09-01/`
и т.д.) и кладёт туда `reports/` и `photos/reys_N/` за этот день. Общий
`dashboard.xlsx` лежит в корне папки (это один сводный файл по всем
рейсам, не по дням).

Если что-то с доступом всё же не сработает — бот **не падает**, загрузка
просто пропускается, а рейс продолжает нормально работать локально,
ничего не теряется.

⚠️ **Важно про секреты**: `MS_CLIENT_SECRET` — это боевой пароль
приложения с доступом к вашему OneDrive. Он уже один раз "засветился" в
переписке (вы прислали его мне, чтобы не делать новую Azure-регистрацию).
Это нормально для разового переноса, но саму папку `.env` никогда не
коммитьте в git и не пересылайте дальше без необходимости. Если когда-то
захотите — секрет можно перевыпустить в Azure (**Certificates & secrets**)
без пересоздания всего приложения, старый после этого перестанет работать
и его нужно будет заменить в `.env` обоих ботов.

## Структура проекта

```
bot.py            — обработчики Telegram (весь диалог с водителем)
checklists.py     — тексты всех чек-листов (легко редактировать формулировки)
database.py       — SQLite: водители, машины, рейсы, ответы, фото, инциденты
reports.py        — сборка .docx отчёта по рейсу
onedrive.py       — загрузка в OneDrive + обновление dashboard.xlsx
keyboards.py      — кнопки (inline-клавиатуры)
states.py         — шаги диалога (FSM)
config.py         — настройки из .env
data/             — база, фото, отчёты, dashboard.xlsx (создаётся сама)
```

## Деплой на Render

В репозитории уже есть `render.yaml` (Render Blueprint) — задаёт нужный тип
сервиса (background worker, не web — бот работает через polling, не webhook)
и постоянный диск для базы/фото/отчётов (`data/`), которые иначе стирались бы
при каждом передеплое.

1. Залейте репозиторий на GitHub (см. ниже)
2. В Render: **New** → **Blueprint** → выбрать этот репозиторий → Render
   сам прочитает `render.yaml` и предложит создать сервис `trancom-driver-bot`
3. Render попросит заполнить переменные окружения, помеченные `sync: false`
   (они специально не хранятся в `render.yaml`, чтобы секреты не попадали
   в git) — возьмите значения из вашего `.env`:
   `BOT_TOKEN`, `MANAGER_CHAT_IDS`, `MS_TENANT_ID`, `MS_CLIENT_ID`,
   `MS_CLIENT_SECRET`, `MS_SHARE_URL`
4. **Create** — Render соберёт и запустит бота автоматически

После первого деплоя каждый `git push` в основную ветку будет
передеплоивать бота (`autoDeploy: true` в `render.yaml`).

## Как залить на GitHub

Если ещё не заливали:

```bash
cd trancom_bot
git init
git add .
git commit -m "TRANCOM driver checklist bot"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<имя-репозитория>.git
git push -u origin main
```

`.gitignore` уже настроен так, что `.env` (секреты) и папка `data/`
(база, фото, отчёты конкретных рейсов) в git не попадают — это то, что и
нужно, эти данные либо секретны, либо специфичны для конкретного сервера.

## Что стоит доделать перед боевым использованием

- **Хостинг**: сейчас бот запускается командой `python bot.py` и работает,
  пока открыт терминал/сервер. Для продакшена — поднять на любом VPS
  под systemd (или Docker), чтобы работал круглосуточно
  и переживал перезагрузки.
- **Список машин заранее**: сейчас водитель может добавить новую машину
  сам через "➕ Інше авто" — если хотите закрытый список, можно быстро
  добавить админ-команду для менеджера, которая добавляет машины в базу.
  Могу сделать.
  - **Резервное копирование** SQLite-базы `data/trancom.db` (простой cron
    с копированием файла, либо сразу перейти на Postgres при росте парка).
- **Этап "04 Під час руху"** сейчас проходится один раз (как остальные) —
  если нужны периодические напоминания в пути (каждые N часов), это
  отдельная фича, могу добавить.
